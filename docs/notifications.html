Powiadomienia

System powiadomień informuje administratora o ważnych zdarzeniach w aplikacji — błędach cyklu cron, martwych linkach, problemach z dostarczaniem e-maili i innych sytuacjach wymagających uwagi.

Dostęp do powiadomień

Ikona dzwonka w prawym górnym rogu paska nawigacyjnego wyświetla liczbę nieprzeczytanych powiadomień (czerwona odznaka). Kliknięcie ikony lub linku w menu przechodzi do pełnej listy powiadomień (?action=notifications).

Lista powiadomień

Tabela powiadomień zawiera następujące kolumny:

Kolumna Opis
Data Data i godzina wygenerowania powiadomienia
Komponent Podsystem, który wygenerował powiadomienie (np. cron, email, broken_links, geo_cache)
Ważność Poziom istotności: Info, Ostrzeżenie, Błąd lub Krytyczny
Tytuł Krótki opis zdarzenia; nieprzeczytane powiadomienia są wyróżnione pogrubieniem
Akcje Przycisk "Szczegóły" (otwiera modal z pełną treścią) i przycisk oznaczenia jako przeczytane

Poziomy ważności

Poziom Kolor Kiedy używany
Info Niebieski Zdarzenia informacyjne, np. zakończenie zadania cron bez błędów
Ostrzeżenie Żółty Sytuacje wymagające uwagi, np. stara baza danych GeoIP, długi czas wykonania cron
Błąd Czerwony Niepowodzenie operacji, np. błąd wysyłki e-maila, nieudane sprawdzenie linku
Krytyczny Czerwony Poważne błędy wymagające natychmiastowej reakcji

Filtry

Listę można zawęzić za pomocą trzech filtrów:

Filtr Opcje
Komponent Wybierz konkretny podsystem lub "Wszystkie"
Ważność Info / Ostrzeżenie / Błąd / Krytyczny lub "Wszystkie"
Status Nowe (nieprzeczytane) / Przeczytane lub "Wszystkie"

Szczegóły powiadomienia

Kliknięcie przycisku Szczegóły otwiera modal z pełnymi informacjami:

  • Data, komponent, ważność i tytuł
  • Treść wiadomości (pole message)
  • Dane kontekstowe w formacie JSON (np. lista adresów URL z błędem, kod odpowiedzi HTTP)
  • Status odczytu wraz z datą przeczytania

Oznaczanie jako przeczytane

Powiadomienie można oznaczyć jako przeczytane na dwa sposoby:

  • Pojedynczo — przycisk z ikoną ptaszka w kolumnie "Akcje" przy danym wierszu.
  • Wszystkie naraz — przycisk Oznacz wszystkie jako przeczytane widoczny w nagłówku strony, gdy istnieją nieprzeczytane powiadomienia.

Źródła powiadomień

Powiadomienia są generowane automatycznie przez różne komponenty systemu:

Komponent Przykładowe zdarzenia
cron Błąd wykonania zadania cron, timeout, wyjątek PHP
email Nieudana wysyłka powiadomienia e-mail (np. raport o martwych linkach)
broken_links Wykrycie martwych linków podczas automatycznego sprawdzania
geo_cache Błąd aktualizacji bazy danych GeoIP, przestarzałe dane
Wskazówka: Zadanie cron send_email_notifications może wysyłać podsumowanie powiadomień e-mailem. Skonfiguruj adres e-mail w Ustawieniach → Email.

Paginacja

Lista jest stronicowana. Linki nawigacyjne (Poprzednia / Następna / numery stron) pojawiają się na dole tabeli, gdy powiadomień jest więcej niż jeden ekran. Aktywne filtry są zachowywane przy przechodzeniu między stronami.
